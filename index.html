01 · Project overview

What we are building and what the prototype should prove.

INPUTS

Weekly disease reports

Start with reliable historical or weekly district-level data. Begin with Tamil Nadu and 2–3 diseases.

ANALYSIS

Forecast + anomaly detection

Estimate near-term case trends and flag unusual increases against a district's recent baseline.

OUTPUT

District risk dashboard

Show district risk, trend charts, map view, and a plain-language explanation for each alert.

Scope guardrail: Alerts are signals for human review. Do not claim certainty, diagnose people, or replace public-health authorities.

04 · GitHub collaboration guide

One shared repository keeps code and project files in sync.

One-time setup

1. Create one GitHub repository

One teammate creates a repository named epialert and invites the other two as collaborators.

2. Clone itgit clone https://github.com/OWNER/epialert.git
3. Create a local Python environmentpy -3.13 -m venv .venv.venv\\Scripts\\activate
4. Install dependenciespip install -r requirements.txt

Daily routine

1. Get the latest changes firstgit pull origin main
2. Work on your agreed files

Tell the team before editing a file owned by someone else.

3. Commit and pushgit statusgit add .git commit -m "Add weekly data cleaning"git push origin main
4. Teammates updategit pull origin main
If push is rejected: run git pull --rebase origin main, resolve conflicts carefully, then push again. If unsure, pause and ask the team. Also add .venv/, __pycache__/, and *.pyc to .gitignore. Never upload the virtual environment.

Proposed minimum fields for predictions.csv. Confirm names and meanings together before coding against it.

ColumnMeaning
